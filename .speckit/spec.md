# Feature Specification: 券商研报 RAG 智能问答系统

**Feature Branch**: `001-rag-analyst-qa`

**Created**: 2026-07-23

**Status**: Draft

**Input**: User description: "作为券商首席分析师助理，基于 3-5 份研报知识库，快速回答投资者的专业问题。上传研报 → 自动解析 → 自然语言提问 → 基于研报内容给出专业回答 + 标注来源研报名称和页码"

## Clarifications

### Session 2026-07-23

- Q: 回答中标注的"第X页"是 PDF 文件页码还是研报印刷页码？ → A: PDF 文件页码（从 1 开始，与 PDF 阅读器显示一致）
- Q: Claude API 调用失败时是否自动重试？ → A: 不重试，立即返回 502 错误给用户，由用户手动重试
- Q: 多轮对话上下文超出模型窗口时如何处理？ → A: 保留最近 3 轮 Q&A，超出部分滑动窗口截断

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 上传研报并建立知识库 (Priority: P1)

投研团队成员登录系统后，选择 3-5 份 PDF 格式的券商研报文件上传。系统自动解析文件内容、
提取文本和页码信息、将文本切分为语义段落并构建向量索引。上传完成后，用户在界面上看到
已索引的研报列表，包含文件名、页数、状态。索引持久化到本地，重启后无需重新上传。

**Why this priority**: 知识库是所有后续问答功能的基础。没有已索引的研报，问答系统无法
运作。这是 MVP 的硬前置条件。

**Independent Test**: 上传 3 份有效 PDF 研报，验证系统返回索引成功状态，调用知识库状态
接口确认所有文件已索引。重启应用后再次检查知识库状态，确认索引数据持久化。

**Acceptance Scenarios**:

1. **Given** 系统知识库为空，**When** 用户选择 3 份有效 PDF 研报点击上传，**Then** 系统
   显示上传进度条，完成后展示 `已索引: 3份`，列出每份文件名、页数和 "已索引" 状态。

2. **Given** 用户上传的文件中包含 1 份损坏的 PDF 和 2 份有效 PDF，**When** 点击上传，
   **Then** 系统成功索引 2 份有效文件，并在错误列表中提示损坏文件："文件已损坏，无法解析"。

3. **Given** 用户上传 1 份纯图片扫描版 PDF（无可提取文本），**When** 点击上传，**Then**
   系统返回错误："无可提取的文本内容，请提供文字型 PDF"。

4. **Given** 用户上传 1 份 `.docx` 文件，**When** 点击上传，**Then** 系统返回错误：
   "不支持的文件类型，仅接受 PDF"。

5. **Given** 用户已上传 5 份研报（达到上限），**When** 尝试继续上传，**Then** 系统提示
   "知识库最多支持 5 份研报，请删除已有研报后再上传"。

### User Story 2 — 自然语言提问获取专业回答 (Priority: P1)

分析师或基金经理在问答界面输入自然语言问题（如"宁德时代 2025 年产能规划是多少？"），
系统从已索引的研报中检索最相关的段落，利用大语言模型生成专业回答。回答以 🎩 券商首席
分析师助理的口吻呈现，并标注每个信息点的来源——具体到研报名称和页码。

**Why this priority**: 这是系统的核心价值——将研报数据转化为即时可用的专业见解。
与 US1 同为 MVP 的必备功能。

**Independent Test**: 在已有 4 份已索引研报的知识库上，输入 "宁德时代 2025 年产能规划
是多少？"，验证：(a) 返回专业回答，(b) 回答标注至少 1 个来源引用（研报名 + 页码），
(c) 来源引用指向的研报确实包含所述信息。

**Acceptance Scenarios**:

1. **Given** 知识库已索引 3 份以上研报，**When** 用户输入 "宁德时代 2025 年产能规划
   是多少？"，**Then** 系统返回专业回答，回答以 🎩 分析师助理口吻表述，并标注至少一个
   来源："根据《XX证券-XX研报》第X页..."。

2. **Given** 知识库已索引研报，**When** 用户提出研报中未覆盖的问题（如"苹果公司股价
   走势"），**Then** 系统回复 "当前知识库中未找到与该问题相关的信息。"，不编造内容。

3. **Given** 用户刚收到一个回答，**When** 用户在同一对话中追问 "能详细说说第二点吗？"，
   **Then** 系统结合之前的对话上下文，基于研报内容进一步展开说明，维持分析师助理身份。

4. **Given** 知识库已索引 4 份研报（来自不同券商），**When** 用户提问一个跨文档议题，
   **Then** 系统同时检索所有文档，回答中可引用多份不同券商研报的来源。

### User Story 3 — CLI 命令行问答 (Priority: P2)

偏好终端操作的分析师可以在命令行中直接提问，无需打开浏览器。CLI 与 Web 共用同一套
后端 API，行为一致。

**Why this priority**: 终端是许多分析师和研究员的高频工作环境，CLI 能显著降低使用
摩擦。但相比 Web UI，它是锦上添花的通道，MVP 后迭代。

**Independent Test**: 在终端执行 `python -m backend.cli query "宁德时代 2025 年产能
规划"`，验证输出包含专业回答和来源标注，与 Web 界面返回结果一致。

**Acceptance Scenarios**:

1. **Given** 后端服务正在运行且知识库已初始化，**When** 用户在终端执行
   `python -m backend.cli query "问题"`，**Then** 终端输出带来源标注的专业回答。

2. **Given** 后端服务正在运行，**When** 用户执行 `python -m backend.cli status`，
   **Then** 终端输出已索引研报列表（文件名、页数、索引时间）。

---

### User Story 4 — 检索参数可调实验对比 (Priority: P3)

投研人员或系统管理员希望在 Web 界面调整检索参数——chunk_size（200/400/600/800）和
相似度阈值（0.3/0.5/0.7）——以对比不同参数组合下的回答质量变化。

**Why this priority**: 参数调优是 RAG 系统持续优化的重要手段，但它不影响核心功能闭环。
适合在 MVP 稳定运行后作为增强功能加入。

**Independent Test**: 在参数面板将 chunk_size 从默认 512 切换到 400，相似度阈值从
0.5 切换到 0.7，重新提问，验证检索到的片段数量和内容有所变化，且来源卡片显示新的
相似度分数。

**Acceptance Scenarios**:

1. **Given** 知识库已有索引，**When** 用户将 chunk_size 滑块从 512 调至 200 并提问，
   **Then** 系统用新参数重新检索并生成回答，来源卡片展示的片段长度明显变短。

2. **Given** 知识库已有索引，**When** 用户将相似度阈值从 0.5 调至 0.7，
   **Then** 检索结果片段数量可能减少（因过滤了低分片段），来源卡片显示的分数均 ≥ 0.7。

### Edge Cases

- **上传同名研报**：MVP 阶段默认覆盖旧索引并重建，系统在上传前给出覆盖提示。v1.1 可扩展为保留历史版本
- **超大 PDF (>100MB)**：系统拒绝上传，提示 "文件大小超过 100MB 限制，请压缩后重试"
- **过长问题 (>2000 字)**：系统拒绝处理，提示 "问题长度超过 2000 字符限制，请精简后重新提问"
- **后端服务重启**：知识库索引自动从本地磁盘加载，10 秒内恢复可用，无需手动操作
- **API 密钥未配置或余额耗尽**：系统返回友好错误提示 "LLM 服务暂时不可用，请检查 API 配置"，不暴露底层密钥细节，后端记录详细日志
- **Claude API 瞬时故障（网络抖动/503）**：系统不自动重试，立即返回 502 "LLM 服务响应超时，请稍后重试"，由用户判断是否手动重试
- **并发操作**：MVP 阶段为单用户本地部署，无并发冲突。v1.1 如需多用户支持，索引写入操作加文件锁保护

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持用户上传 1-5 份 PDF 格式的券商研报文件，单次可批量选择多个文件
- **FR-002**: 系统 MUST 自动解析 PDF 文件，提取文本内容和页码信息
- **FR-003**: 系统 MUST 将提取的文本切分为语义段落（chunk），每个分块携带来源元数据
  （文档名、页码、分块序号）
- **FR-004**: 系统 MUST 将分块文本转化为向量表示并存入向量索引，索引持久化到本地磁盘
- **FR-005**: 系统 MUST 支持跨文档检索——用户提问时同时搜索所有已索引研报，不限定单一文档
- **FR-006**: 系统 MUST 以 🎩 某券商首席分析师助理的身份和口吻生成回答，风格专业严谨
- **FR-007**: 系统 MUST 在每份回答中标注信息来源，至少包含研报名称和 PDF 文件页码
  （从 1 开始，与 PDF 阅读器页数一致），格式为 "根据XX证券《XX研报》第X页..."
- **FR-008**: 系统 MUST 在研报内容无法覆盖用户问题时，明确告知用户而非编造答案
- **FR-009**: 系统 MUST 提供知识库状态查询接口，返回已索引研报数量、文件名、页数和索引时间
- **FR-010**: 系统 MUST 支持多轮对话上下文延续（用户可追问），保留最近 3 轮 Q&A
  作为上下文，超出部分采用滑动窗口截断
- **FR-011**: 系统 MUST 将所有 API 密钥和敏感配置从环境变量读取，禁止硬编码
- **FR-012**: 系统 MUST 在上传阶段区分处理有效和无效文件——部分文件失败不阻塞有效文件的索引
- **FR-013**: 系统 SHOULD 在上传同名研报时提示用户是否覆盖旧索引
- **FR-014**: 系统 SHOULD (v1.1) 允许用户在 Web 界面调整检索参数：chunk_size
  和相似度阈值
- **FR-015**: 系统 SHOULD (v1.1) 提供 CLI 命令行接口，支持终端提问和状态查询

### Key Entities

- **研报 (Report)**: 券商发布的 PDF 分析报告。关键属性：文件名、券商机构、页数、
  上传时间、索引状态。
- **分块 (Chunk)**: 研报文本的语义段落切片。关键属性：所属研报、页码、文本内容、
  向量表示、分块序号。
- **问答记录 (Query)**: 用户的一次提问。关键属性：问题文本、生成的回答、引用的
  来源列表（研报名 + 页码 + 原文片段 + 相似度分数）、时间戳。
- **知识库配置 (KnowledgeBase)**: 全局索引参数。关键属性：嵌入模型名称、
  chunk_size、chunk_overlap、已索引文档列表。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在 5 分钟内完成首次上传 3 份研报（从打开上传页面到知识库就绪）
- **SC-002**: 单份 30 页研报的解析和索引时间不超过 60 秒
- **SC-003**: 用户提问后 30 秒内获得完整回答（含来源引用）
- **SC-004**: 90% 的回答中包含至少一个准确的来源引用（研报名 + 页码与原文一致）
- **SC-005**: 系统在研报未覆盖问题时 100% 明确告知而非编造（基于 20 个跨主题测试问题）
- **SC-006**: 系统重启后知识库索引在 10 秒内自动恢复可用，无需重新上传
- **SC-007**: 用户在新手引导后无需外部帮助即可完成首次上传和提问（通过可用性测试验证）

## Assumptions

- 用户上传的 PDF 为文字型（非扫描图片型），文本可直接提取
- 研报语言为中文，嵌入模型和 LLM 均支持中文
- 系统为单用户或小团队使用，无需多用户权限和认证系统
- Claude API 可用且用户已获取有效的 API 密钥
- 系统部署在分析师本地机器上运行，研报数据不离开公司网络
- 3-5 份研报共约 150 页，总文本量在嵌入模型和 LLM 上下文窗口可处理范围内
- MVP 阶段上传同名研报的行为默认为覆盖旧索引（v1.1 可加入确认提示）
- 前端框架选择（React/轻量 SPA）和技术细节由 plan 阶段确定
